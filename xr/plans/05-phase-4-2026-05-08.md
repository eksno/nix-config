# Phase 4 — N-screen curved layout + per-workspace captures

Date: 2026-05-08
Status: in progress

## Goal

In an active breezy-hyprland session, present **N curved virtual
screens arranged in a horizontal arc around the user's head**, each
screen showing a **different Hyprland workspace**. User can look left
to see workspace 1, center for workspace 5, right for workspace 9.

Currently breezy-hyprland gives a single curved screen mirroring the
laptop's only wl_output, with all of Hyprland's workspaces folded into
that one display. Phase 4 splits them apart.

## Architecture

Two independent sub-pieces, each verifiable on the laptop screen
without needing DP altmode:

### 4A — Per-workspace captures via headless wl_outputs

Hyprland already supports virtual outputs:

```
hyprctl output create headless    → creates HEADLESS-N
hyprctl output remove HEADLESS-N  → removes it
```

Each headless output appears as a wl_output that wlr-screencopy can
capture. WayVR enumerates wl_outputs at startup
(`overlays/screen/wl.rs:create_screens_wayland`) and creates one
overlay per output — so N headless outputs ⇒ N captures with no WayVR
code changes needed.

Workspace-to-output assignment uses Hyprland's
`moveworkspacetomonitor` dispatcher. New workspaces are auto-bound to
the newest output (verified 2026-05-08: created HEADLESS-2, workspace
2 was auto-assigned).

Implementation:

- Extend `system/lib/xr/breezy-hyprland/launcher.nix` to:
  1. Read `BREEZY_N_SCREENS` env var (default 4)
  2. Before starting monado: `hyprctl output create headless` × N
  3. Move workspaces 1..N to the new outputs:
     `hyprctl dispatch moveworkspacetomonitor "I HEADLESS-(I+1)"`
  4. In cleanup trap: `hyprctl output remove HEADLESS-X` for each
     created output, AFTER stopping monado/wayvr
- Track the created output names in a shell array so cleanup is
  resilient if Hyprland renames or reorders.

Verification (no glasses needed):
- Run breezy-hyprland in a terminal; while it's running,
  `hyprctl monitors -j | jq '.[].name'` shows
  `eDP-1`, `DP-2`, `HEADLESS-2..N+1`.
- Each `HEADLESS-X` has its assigned workspace as its activeWorkspace.
- Ctrl+C cleanly removes the headless outputs.

### 4B — Curved arc layout in WayVR

Currently every screen overlay is created with the same transform
(`screen/mod.rs:52-56`):

```rust
transform: Affine3A::from_scale_rotation_translation(
    Vec3::ONE * 1.5 * desktop_view_scale,
    Quat::from_rotation_z(angle),  // angle is for upright_screen_fix only
    vec3(0.0, 0.0, -0.5),          // (0, 0, -0.5) for ALL screens — they stack
),
```

For N screens, distribute them in a horizontal arc:

- Radius `R = 0.6` m (slightly farther than current 0.5 to leave room
  for screens to sit on the arc)
- Angular spacing `Δθ = 0.6` rad (~34°) per screen — adjustable
- Index i in 0..N: `θ_i = (i - (N-1)/2) * Δθ`
- Position: `(R · sin θ_i, 0, -R · cos θ_i)`
- Rotation: `Quat::from_rotation_y(-θ_i)` so each screen's −Z faces
  the user

Implementation:

- Add an optional `arc_index: Option<(usize, usize)>` parameter to
  `create_screen_from_backend(name, transform, session, backend, arc_index)`
- If `arc_index` is `Some((i, n))`, compute the arc transform
  (overriding the current static `vec3(0, 0, -0.5)`)
- Plumb `(i, n)` through `wl.rs:create_screens_wayland` — `n` is
  `wl.outputs.len()`, `i` is the enumeration index
- Apply as a Mesa-anv-side patch in
  `system/lib/xr/wayvr-anv/patches/curved-arc-layout.patch`

Verification:
- After rebuild, breezy-hyprland session: visually inspect on the
  laptop wayvr `--show` window (mirror of XR scene) — N curved
  screens fan out left-to-right.
- Without DP altmode, the glasses panel still won't show anything,
  but the laptop-side `--show` mirror is sufficient to verify the
  layout math.
- Once altmode comes back, real visual check on the glasses.

## Sequencing

1. **4A first** — pure shell-script work, no Rust rebuild required.
   Risk: low. If it breaks, revert is instant. Validates the
   per-workspace capture concept end-to-end.

2. **4B second** — depends on 4A landing (otherwise we have only one
   wl_output and no arc to distribute). Rust patch + cargo rebuild
   (~5–15 min via `update-without-update.sh`).

## Out of scope for Phase 4

- **Curvature per screen**: WayVR already curves each individual
  screen panel (`overlays/screen/mod.rs:51` `curvature: Some(0.15)`).
  Don't touch.
- **Recentering** at runtime: `breezy-recenter` (Super+R) already
  re-orients the whole scene. The arc rotates with it.
- **Workspace-aware capture refresh**: if the user switches workspace
  inside Hyprland, the headless output keeps its assigned workspace.
  The user navigates by looking at a different screen, not by
  dispatching workspace switches.
- **Configurable per-screen arc spacing or per-screen content**:
  fixed N, fixed Δθ, fixed assignment (workspace I → screen I).
  Could be tweaked later if needed.
- **DP altmode dependency**: 4A and 4B can be implemented and
  visually verified entirely without DP altmode (laptop-side wayvr
  --show mirror). Real-glasses verification waits for the EC
  recovery (see `memory/xr-lewis-ec-refuses-altmode.md`).
